커넥터 · 메일

Gmail과 구글 캘린더를 Claude에 연결해, 05차시 보고서를 실제 메일함과 일정으로 내보냅니다. 거절 · 사과 · 독촉 · 요청 네 유형의 껄끄러운 메일을 구조로 쓰고, 안내문을 한 번에 여러 장 만들며 "밖으로 나가는 지점엔 사람이 선다"는 원칙을 몸으로 익힙니다.

오늘의 가상 상황

지난 시간에 주간보고를 5분으로 줄였는데, 그 보고서는 아직 화면 안에 있습니다. 답장을 미뤄 둔 껄끄러운 메일 두 통과 보내야 할 독촉 메일 한 통, 당첨자 6명에게 보낼 안내문도 그대로입니다. 오늘은 전부 화면 밖으로 내보냅니다. 이번엔 진짜로 옆자리 짝꿍의 메일함까지요.

1. 커넥터란

Claude를 내가 이미 쓰는 서비스에 이어 주는 연결 통로입니다.

지금까지는 Claude가 만든 결과를 복사해서 메일이나 캘린더에 붙여 넣었습니다. 커넥터를 붙이면 Claude가 그 서비스의 내용을 직접 읽고, 내가 허락한 범위 안에서 메일을 보내거나 일정을 만듭니다. 복사 · 붙여넣기가 사라집니다. 연결은 Claude 설정 → 커넥터에서 서비스별로 하나씩 합니다. 대화창에서 맡기는 Cowork에서도 연결한 커넥터를 그대로 씁니다.

연결 전에 두 가지

개인 구글 계정으로 하세요. 연결은 그 서비스에 대한 접근 권한을 주는 것이라, 회사 계정은 사내 보안 정책을 먼저 확인합니다. 그리고 설정 → 개인정보에서 모델 개선(학습 허용)을 끄세요. 커넥터를 붙이면 진짜 내 메일 내용이 대화 안으로 들어옵니다.

실습 A — Gmail 연결 (최초 1회)

설정 → 커넥터 → 목록에서 Gmail 연결 → 구글 계정 로그인 → 권한 승인.

막히면
  • 로그인 창이 안 뜸 · 브라우저 팝업 차단 해제
  • 구글 계정이 여러 개 · 실습할 개인 계정을 골랐는지 확인
  • 권한 체크박스가 여러 개 · 전부 체크해야 읽기 · 보내기가 다 됨
  • 연결은 됐는데 메일을 못 찾음 · 대화창 도구 메뉴에서 Gmail이 켜져 있는지 확인 후 새 대화

2. Gmail로 읽고 내보내기

오늘 받는 사람은 둘뿐입니다. 나, 그리고 짝꿍. 잘못 나가도 수습이 되는 상대입니다.

Gmail 커넥터를 연결하면 Claude가 직접 발송 · 답장 · 전달까지 할 수 있습니다. 대신 기본 설정에서는 매 동작 전에 승인 창이 뜹니다. 승인 창이 게이트, 버튼을 누르는 손이 검수입니다. 창이 뜨는 것만으로는 아무것도 막지 못합니다. 받는 사람 · 제목 · 본문을 읽고 누르는 것까지가 검수입니다. 승인 설정을 '항상 허용'으로 바꾸지 마세요.

실습 B — 내 메일함을 자료로 쓰기 (읽기)

그린컵 Project 안에서 새 대화를 엽니다. 지금 연결한 건 진짜 내 메일함이라, 대괄호에는 내 실제 일의 단어를 넣으세요.

읽기 두 가지
내 메일함에서 지난 2주간 받은 메일 중, 처리해야 하는데 놓친 게 있는지 찾아 줘. 있으면 출처 메일 제목과 함께 정리해 줘.
최근 메일에서 [내 업무 키워드]가 언급된 걸 찾아서, 반복되는 문제가 있는지 짚어 줘.

확인할 것 — 근거(출처 메일 제목)를 확인할 수 있나요? "없습니다"가 나와도 성공입니다. 없는 걸 그럴듯하게 지어내면 그게 사고입니다.

실습 C — 나에게 보내는 '월요일 브리핑' 예약하기

커넥터에는 예약 발송 기능이 없습니다. 초안은 AI, 예약은 Gmail, 확인은 사람이 나눠 맡습니다.

  1. 초안 만들기 — 05차시 주간보고 파일을 첨부하고:
    초안 저장
    첨부한 주간보고서를 바탕으로, 내 주소로 보내는 메일 초안을 Gmail에 저장해 줘.
- 받는 사람: [내 실제 주소]
- 제목: [월요일 브리핑] 6월 3주차 실적 — 매출 +26%
- 본문: 검수를 통과한 핵심 요약 3줄 + 이번 주 챙길 일 3가지
- 톤: 월요일 아침의 내가 30초 만에 읽고 바로 움직일 수 있게, 담백하게
  2. Gmail에서 확인하고 예약 — 임시보관함에서 초안을 찾아 한 번 읽습니다(이게 게이트). 보내기 옆 화살표 → 예약 발송 → 월요일 오전 8시.
  3. 확인 — 월요일 아침 메일함에 브리핑이 와 있으면 성공입니다. 데이터 → 보고서 → 검수 → 요약 메일 → 예약 발송, 처음으로 화면 밖으로 나갔습니다.

3. 캘린더에 후속 일정 꽂기

메일은 한 통이지만 일정은 한 번에 여러 개가 생깁니다. "목록 먼저"로 게이트를 하나 더 세웁니다.

실습 D — 보고서의 계획을 일정으로
  1. 캘린더 연결 — 설정 → 커넥터 → Google Calendar. Gmail과 같은 개인 계정으로 로그인합니다.
  2. 목록 먼저 받기
    일정 만들기 전 목록
    이 보고서의 '이슈 및 다음 주 계획' 항목을 내 구글 캘린더 일정으로 만들어 줘.
각 항목마다 적당한 요일에 30분씩, 제목 앞에 [주간보고] 를 붙여서.
만들기 전에 어떤 일정을 언제 만들지 목록으로 먼저 보여 줘.
  3. 골라내기 — "방금 목록에서 [확인필요]가 남아 있는 항목은 빼고, 이번 주에 내가 실제로 착수할 일만 캘린더에 만들어 줘." 실제 업무에선 "내 이름이 담당인 것만, 담당자 미정은 손대지 말고"

"만들기 전에 목록으로 먼저 보여 줘"를 빼면 일정이 우수수 생기고 하나씩 지워야 합니다. 03차시에서 배운 계획 단계에서 멈추기와 같은 원리입니다. 보고서 쓰고 나서 따로 일정 잡는 30분이 이 흐름으로 사라집니다. 10차시 회의록의 할 일 표도 같은 방식으로 캘린더에 보냅니다.

4. 껄끄러운 메일, 30분에서 5분으로

"정중하게 써 줘"로는 부족합니다. 유형마다 빠지면 안 되는 칸이 정해져 있습니다.

유형구조핵심 지시빠뜨리면
거절감사 → 명확한 거절 → 이유(간단히) → 대안 · 여지"정중하지만 여지 없이 명확하게"이유만 길면 변명, 대안 없으면 관계 끊김
사과인정 → 원인(짧게) → 보상 · 조치 → 재발 방지"인정할 것만 인정하고 대안 제시"보상 없이 사과만 = 무성의
부탁 · 독촉상황 확인 → 필요한 것 → 명확한 기한 → 도울 것 제안"상대 사정 언급 + 기한은 명확히"기한이 모호하면 또 밀림
요청배경 → 구체적 요청 → 상대 이득 → 기한 · 회신 방법"내가 원하는 행동을 한 문장으로"배경만 길고 뭘 원하는지 불명확
실습 E — 거절 + 역제안

그린컵 Project 안에서 새 대화를 열고 받은 메일 3종 파일을 첨부합니다. Project 안에서 하면 브랜드 톤과 정책(배송 · 쿠폰)이 자동으로 반영됩니다.

거절 + 역제안
첨부한 첫 번째 메일(단가 20% 인하 요구)에 답장을 써 줘.
우리 내부 한도는 10%야. 5% 할인 + 무료배송 + 각인 서비스로 역제안해 줘.
구조는 감사 → 명확한 거절 → 이유는 '내부 기준'까지만 → 대안.
타사 견적 언급에는 휘둘리지 말고, 우리 강점(품질·A/S)을 한 줄 넣어 줘.

확인할 것 — 거절이 명확한가요? "어려울 것 같습니다"처럼 흐리면 상대가 또 묻습니다. 거절 이유에 없는 수치를 지어내지 않았나요?

거절할 때 이유는 어디까지공개 수준예
조건이 안 맞음간단히"내부 기준상 이번 분기에는 어렵습니다"
우선순위 밀림솔직히"하반기 로드맵이 이미 확정돼 있어"
말 못 할 사정말하지 않되 명확히"검토했으나 이번엔 진행이 어렵습니다"

어디까지 쓸지 지정하지 않으면 AI가 없는 이유를 지어냅니다. 공개 수준을 정하고, 그걸 지시문에 상한선으로 적으세요.

실습 F — 사과 + 보상
사과
두 번째 메일(배송 지연 컴플레인)에 답장. 우리 잘못이 맞아(택배사 지연 + CS 응대 미흡).
구조는 인정 → 원인 짧게 → 보상(전액 환불 또는 재배송 선택 + 3,000원 쿠폰) → 재발 방지 한 줄.
과한 저자세는 피하고, 변명처럼 안 들리게.

확인할 것 — "죄송합니다"가 3번 넘으면 오히려 무성의해 보입니다. "사과는 앞에 한 번만"으로 고쳐 보세요. 선물 날짜가 지났다는 고객의 진짜 손해를 언급했나요? 한 지시 = 한 개선으로 봅니다.

실습 G — 독촉 + 톤 조절

이번엔 내가 먼저 보내야 하는 메일입니다.

독촉
디자인 외주 거래처에 시안 독촉 메일을 써 줘.
원래 납기가 2주 전이었는데 아직 시안을 못 받았어. 다음 달 신제품 촬영 일정이 걸려 있어.
구조는 상황 확인 → 필요한 것 → 명확한 기한(이번 주 금요일 오후 6시) → 우리가 도울 것 제안.
관계는 유지하고 싶으니 탓하는 말투는 빼고, 기한만큼은 흐리지 마.

확인할 것 — 기한이 날짜 · 시간으로 박혀 있나요? 상대 사정을 묻는 한 줄이 있나요? 이어서 "위 세 메일을 각각 더 격식 있게", "절반 길이로"처럼 옷만 갈아입혀 봅니다.

본문을 아무리 잘 써도 안 열리면 소용없습니다. 제목은 [분류] 핵심 + 필요한 행동입니다.

이런 제목 말고이런 제목
"안녕하세요""[문의] 단체주문 200개 단가 협의 요청"
"보고서입니다""[공유] 6월 3주차 주간실적 — 매출 +26%"
"확인 부탁드립니다""[요청] 7/5까지 회신 — 프로모션 예산안 승인"
실습 H — 제목 뽑기
제목
위 세 메일의 제목을 각각 3개씩 뽑아 줘. [분류] 핵심 + 필요한 행동 형식, 30자 이내.

확인할 것 — 제목만 보고 "내가 뭘 해야 하지?"가 풀리나요?

5. 짝꿍 '팀장님'에게 요청 메일 보내기

오늘의 하이라이트입니다. 초안이 아니라 커넥터로 실제 발송합니다.

시작 전에

메일 주소는 개인정보입니다. 짝과 서로 괜찮은지 먼저 묻고 교환하세요. 원치 않으면 받는 사람을 내 주소로 적고 혼자 해도 됩니다.

실습 I — 요청 메일 실제 발송
  1. 무엇을 요청할지 — 짝을 팀장님으로 정하고, 05차시 보고서의 '이슈 및 다음 주 계획'에서 팀장 승인이 필요한 것 하나를 고릅니다. 예 · 박스 모서리 보호재 · 완충재 보강을 다음 주부터 진행할지
  2. 요청 메일 만들기 — 보고서를 첨부하고:
    요청 메일
    첨부한 주간보고서로 팀장님께 보내는 요청 메일을 써 줘.
- 받는 사람: [짝의 실제 주소]
- 요청할 것: [1번에서 고른 것]
- 구조: 배경(보고서 요약 3줄) → 구체적 요청 → 팀장님 입장의 이득 → 회신 기한·방법
- 회신 기한: [날짜·시간까지]
- 제목: [요청] 핵심 + 필요한 행동, 30자 이내
- 메일에 보고서 파일을 첨부하지 말고, 필요한 숫자만 본문에 넣어 줘
- 보내기 전에 받는 사람·제목·본문을 먼저 보여 줘
    마지막 두 줄은 커넥터로 보낼 때 매번 붙이는 습관입니다
  3. 읽고 승인 — 주소가 짝의 것인지, 숫자가 05차시 검수 결과와 같은지, 팀장님의 이득이 들어갔는지, 기한이 날짜 · 시간인지 봅니다. "이대로 보내 줘" → 승인 창에서 한 번 더 읽고 승인합니다.
  4. 받은 쪽 피드백 — 짝이 보낸 메일을 내 Gmail에서 열고 팀장이 된 기분으로 세 가지만 말해 줍니다. 제목만 보고 열고 싶었나? 스크롤 없이 첫 화면만 보고 결정할 수 있나? 언제까지인지 바로 보이나?

실습 C는 초안 → 내가 Gmail에서 예약, 실습 I는 Claude가 발송 → 내가 승인입니다. 누르는 버튼은 달라도 나가기 직전에 사람이 읽고 누른다는 건 같습니다. 짝의 피드백은 받는 사람 입장의 검수입니다.

조절 구간 — 빨리 끝낸 짝은 컴플레인 주고받기. A가 받은 메일 3종의 두 번째(배송 지연) 내용을 고객 입장에서 짝에게 보내고, B가 "내 메일함에서 '배송 지연' 메일을 찾아 인정 → 원인 짧게 → 보상 → 재발 방지로 답장해 줘. 보내기 전에 먼저 보여 줘"로 같은 스레드에 답장. 보상이 Project의 정책 기준으로 나왔는지 확인합니다.

6. 안내문 양산 — 템플릿 1개 × 데이터 N행

당첨 안내문 30명, 거래처 공지 20곳. 내용은 거의 같고 이름 · 상품 · 날짜만 다릅니다.

템플릿에서 케이스마다 바뀌는 부분을 {{변수}}로 표시하고, 변수 값은 엑셀 표로 둡니다. 한 행 = 한 문서. 둘을 함께 주고 "각 행을 넣어서 사람마다 만들어 줘"라고 하면 됩니다.

실습 J — 당첨 안내문 6장, Cowork로 파일까지
  1. 맡기기 — 새 대화에 두 파일을 첨부하고:
    양산
    이 안내문 템플릿의 변수를 당첨자 데이터 각 행에 맞춰 채워서, 6명 각각의 완성된 안내문을 만들어 줘.
사람마다 따로 워드 파일로, 파일 이름은 안내문_[이름].docx.
  2. 검수 — "방금 만든 안내문에서 각 사람의 당첨상품·마감일이 데이터와 정확히 일치하는지 표로 대조해 줘."
  3. 개수 세기 — 결과가 정확히 6개인가요? 6행인데 5개면 그게 케이스 누락입니다.
준비물
  • 안내문 템플릿 · notice_template.docx, {{변수}} 포함
  • 당첨자 케이스 데이터 · winner_cases.xlsx, 6명
양산 검수 포인트놓치면
① 변수 매칭엉뚱한 사람에게 엉뚱한 상품이 감 — 가장 흔한 사고
② 케이스 누락한 명이 통째로 빠짐. 사람 수가 많을수록 조용히 늘어남
③ 발송 전 사람 확인외부로 나가는 문서라 되돌릴 수 없음

반복해서 쓸 안내문이라면 템플릿은 Project에 올려 두세요. 오늘은 연습용 한 회차라 첨부로 씁니다.

조절 구간 — 빠른 수강생은 "같은 내용을 문자(SMS)용 2~3줄 버전으로도 6명분", "VIP 고객(이수진)에게는 더 정중한 톤으로". SMS도 6개인지, 이수진 님 것만 톤이 바뀌었는지 확인합니다. 받은 메일 3종의 세 번째(콜라보 제안)에 "관계는 남기되 사유는 '이번 분기 리소스' 선에서" 거절하는 것도 좋습니다.

7. 오늘 사람은 어디에 섰나

되돌릴 수 없거나 밖으로 나가는 지점에 사람이 있습니다. 우연이 아니라 자동화 설계의 원칙입니다.

단계누가왜
메일 초안 · 일정 목록 제안 · 안내문 6장AI아직 아무것도 안 바뀜, 반복 작업
예약 걸기 · 발송 승인 버튼사람되돌릴 수 없음
메일이 읽히는지 피드백사람 (짝꿍)받는 사람만 알 수 있음
일정 생성 승인사람내 캘린더가 바뀜
행 수 · 변수 대조사람엉뚱한 사람에게 엉뚱한 내용이 감
실습 끝나면 연습 흔적 정리

Gmail 임시보관함의 연습 초안 삭제, 월요일 브리핑은 도착 확인 후 삭제, 캘린더의 [주간보고] 일정 삭제("방금 만든 [주간보고]로 시작하는 일정 목록 보여 줘"로 찾으면 편합니다). 연결 자체를 끊고 싶으면 설정 → 커넥터에서 해제합니다.

지금은 매주 내가 대화를 열어 시켜야 합니다. 다음 차시에 이걸 예약 작업으로 굳혀, 정해진 시간에 알아서 돌아가게 만듭니다.

8. 정리 · 자주 묻는 질문 · 안 될 때

한 줄 요약

커넥터는 읽기와 쓰기가 다 되고, 승인 창이 게이트입니다. 여러 개가 한 번에 바뀌는 일은 "목록 먼저"로 게이트를 하나 더 세웁니다. 껄끄러운 메일은 유형별 구조로 — 거절엔 대안, 사과엔 보상, 독촉엔 기한. 양산은 변수 매칭과 개수를 셉니다.
