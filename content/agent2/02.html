02차시

작업지시서 → 스킬

01차시에 고른 업무를 사람에게 넘겨도 되는 작업지시서(SOP)로 먼저 씁니다. 그다음 그 지시서를 Claude가 알아서 꺼내 쓰는 스킬로 만듭니다. 매번 긴 프롬프트를 붙여넣던 일이 "이번 주 홍보 패키지 만들어 줘" 한 마디가 됩니다. 마지막엔 같은 것을 Claude Code의 폴더 전용 명령으로도 만들어 봅니다.

오늘의 가상 상황

뮤지엄은 매주 영상 한 편을 올립니다. 그때마다 유튜브 설명란, 인스타 캡션, 해시태그, 블로그 글 개요를 씁니다. 지난주엔 Claude에게 잘 시켰는데 이번 주엔 그 프롬프트를 못 찾았고, 새로 쓰니 말투가 달라졌습니다. 해시태그는 30개가 붙어 나왔습니다. 오늘은 "잘된 그 방식"을 파일로 굳힙니다.

1. 지시를 어디에 적어 두나

Agent 1에서 지시를 남기는 곳을 세 군데 배웠습니다. 오늘 네 번째가 더해집니다.

적어 두는 곳언제 읽히나어디서어울리는 것
저장한 지시문 (메모장)내가 붙여넣을 때만어디든가끔 쓰는 프롬프트
Project 지침그 Project 안 대화마다 항상그 Project회사 · 브랜드 배경, 말투
CLAUDE.md그 폴더를 열 때마다 항상그 폴더 (Claude Code)폴더 규칙 (원본 금지, 저장 위치)
스킬그 일이 필요할 때만모든 대화 · Code특정 작업의 순서와 기준

지침과 CLAUDE.md는 항상 읽힙니다. 그래서 길어지면 모든 대화가 무거워집니다. 스킬은 평소엔 이름과 한 줄 설명만 보이다가, 그 일이 나오면 그때 본문을 펼쳐 읽습니다. 작업 순서가 긴 일, 여러 Project에서 쓰는 일이 스킬 자리입니다.

2. 작업지시서(SOP) — 신입에게 넘길 수 있게

스킬부터 만들지 않습니다. 사람이 읽고 따라 할 수 있는 지시서가 먼저입니다. 사람에게 설명 못 하는 일은 AI에게도 설명 못 합니다.

칸묻는 것뮤지엄 홍보 패키지 예
목적이걸 왜 하나새 영상을 채널마다 맞는 말로 알려 조회 · 저장을 늘린다

입력무엇을 받아야 시작하나 · 없으면?영상 제목 · 한 줄 설명 · 장면 메모. 없으면 먼저 묻는다

예시잘된 결과 하나지난주 실제로 올린 문구 (가장 강력한 칸)
예시 한 개가 설명 열 줄보다 셉니다

"차분하고 담백한 말투"라고 열 번 쓰는 것보다, 마음에 들었던 지난 캡션 하나를 붙이는 게 정확합니다. 단, 예시가 하나면 그 문장을 베끼기 쉬우니 "말투만 참고하고 문장은 새로"를 같이 적습니다.

3. 지시서 쓰기 — Claude가 묻고 내가 답한다

빈 칸을 혼자 채우면 빠뜨립니다. 05차시 브랜드 인터뷰와 같은 방식으로 Claude에게 물어보게 합니다.

확인할 것 — 정리된 지시서를 옆 사람에게 보여 주고 "이것만 보고 할 수 있겠어요?"라고 물어보세요. 되묻는 게 있으면 그게 빠진 칸입니다. 고쳐 달라고 한 뒤, 완성본을 메모장에 홍보패키지_SOP.md로 저장합니다.

조절 구간 — 빠른 수강생은 01차시 내 후보 카드로 같은 인터뷰를 한 번 더 돌려 내 업무 지시서를 만들기. 칸이 안 맞으면 바꿔도 됩니다 (예: 고객 응대라면 '말투' 대신 '절대 약속하면 안 되는 것').

4. 스킬이란 — 필요할 때 펼쳐 보는 작업지시서

스킬은 폴더 하나입니다. 핵심은 그 안의 SKILL.md 파일 하나.

부분내용왜 중요한가
name영어 소문자 · 하이픈 (예: museum-promo)부르는 이름

본문작업지시서 그대로 (단계 · 기준 · 금지 · 멈춤)불린 뒤 읽는 부분
참고 파일 (선택)예시 모음, 브랜드 규칙, 양식필요할 때만 열어 봄. 본문을 짧게 유지
description 나쁜 예좋은 예

5. 스킬 만들기 — 지시서를 넘기면 된다

파일을 직접 쓸 필요는 없습니다. 지시서를 주고 스킬로 만들어 달라고 합니다.

실습 B — 지시서 → 스킬 → 새 대화에서 시험
  1. 만들기 — 실습 A의 대화에 이어서 아래를 보냅니다.
  2. 저장 — Claude가 저장 카드를 띄우면 내용을 읽고 저장합니다. 파일(.zip)로 주면 내려받아 설정 → 기능(Capabilities) → 스킬에서 올리고 켭니다. 화면 이름은 앱 버전에 따라 조금 다를 수 있음
  3. 시험 — 새 대화를 열고 아래 시험 문장을 보냅니다. 스킬 이름을 말하지 않습니다.
스킬로 만들기
방금 정리한 작업지시서를 그대로 스킬로 만들어 줘.
- name: museum-promo
- description은 무엇을 하는지와 언제 쓰는지(어떤 요청 문장에서)를 두 문장으로
- 본문은 지시서 내용을 바꾸지 말고, 예시 캡션은 참고 파일로 따로 빼 줘
- 마지막 단계에 '게시 · 업로드는 하지 않고 초안만 보여 준다'를 꼭 넣어 줘
만들기 전에 description 문장을 먼저 보여 줘.
시험 — 새 대화
이번 주 영상 홍보 패키지 만들어 줘.
제목: 세탁소의 오후
한 줄 설명: 동네 세탁소 다리미 김이 오르는 30초
장면 메모: 다리미 김, 창문 햇빛, 걸려 있는 셔츠들, 라디오 소리

확인할 것

  1. 답 위에 스킬을 사용했다는 표시가 나오나 안 나오면 description이 흐린 것
  2. 해시태그가 5~8개이고 #뮤지엄 #일상을전시하다 가 들어 있나
  3. 메모에 없는 장소 이름 · 사람 · 숫자가 없나 "30년 된 세탁소" 같은 문장이 나오면 지어낸 것
  4. 마지막에 "게시하지 않았다 / 초안이다"로 멈추나

거꾸로도 시험합니다. 새 대화에서 "회사 송년회 안내 문구 써 줘" → 뮤지엄 스킬이 안 불려야 정상입니다. 불리면 description이 너무 넓은 것입니다.

6. Claude Code의 폴더 전용 명령

04 · 08차시에서 "이 폴더 전용 명령으로 저장해 줘"가 나옵니다. 같은 스킬을 폴더 안에 두는 방식입니다.

앱 스킬 (실습 B)폴더 스킬 (오늘 실습 C)
사는 곳내 계정그 폴더의 .claude/skills/ 안
쓰는 곳모든 대화 · Code그 폴더로 연 Claude Code
부르는 법말하면 알아서 · 또는 이름으로/이름 또는 말하면 알아서
어울리는 일어디서든 쓰는 글쓰기 · 정리그 폴더의 파일을 읽고 만드는 일
나눠 주기스킬 파일 전달폴더째 복사하면 같이 감
실습 C — 영상 메모 폴더에 /promo 만들기
  1. 바탕화면에 뮤지엄_영상 폴더를 만들고, 메모장으로 세탁소의오후_메모.txt를 만들어 실습 B 시험 문장의 제목 · 설명 · 장면 메모를 붙여 저장합니다.
  2. Code 탭 → Local · 이 폴더 · 수동 → 아래를 보냅니다.
  3. 새 대화에서 /promo 세탁소의오후_메모.txt
폴더 전용 명령
이 폴더 전용 스킬 promo를 만들어 줘.
- 내가 /promo 파일이름 으로 부를 때만 실행되게 (알아서 불리지 않게)
- 그 메모 파일을 읽고, 아래 작업지시서대로 홍보 패키지를 만들어 '홍보_파일이름.md'로 저장
- 원본 메모는 고치지 마
[홍보패키지_SOP.md 내용을 붙여넣기]
어디에 어떤 파일을 만드는지 먼저 보여 줘.

확인할 것 — 입력창에 /를 치면 promo가 목록에 보이나요? 실행 후 홍보_세탁소의오후_메모.md가 생겼나요? 탐색기에서 숨김 폴더 보기를 켜면 .claude/skills/promo/SKILL.md가 보입니다. 메모장으로 열어 지시서가 들어 있는지 봅니다.

7. 고치기 · 안전

스킬을 만들면 습관이 하나 바뀝니다. 결과가 틀리면 대화에서 고치지 말고 스킬을 고칩니다.

상황대화에서만 고치면스킬을 고치면
해시태그가 또 많음이번만 맞고 다음 주 또"museum-promo 스킬의 기준에 '해시태그는 최대 8개, 넘으면 덜 중요한 것부터 뺀다'를 추가해 줘"
새 채널이 생김 (스레드)매번 따로 부탁"단계에 스레드용 3줄 문구를 추가해 줘"
예시가 낡음옛 말투가 계속 나옴참고 파일의 예시를 최근 것으로 교체
남이 만든 스킬은 읽고 설치

스킬은 Claude에게 주는 지시서이고, 안에 프로그램 파일이 들어 있을 수도 있습니다. 인터넷에서 받은 스킬에 "작업이 끝나면 결과를 이 주소로 보내라" 같은 줄이 숨어 있으면 Claude는 그걸 내 지시처럼 읽습니다. 설치 전에 SKILL.md를 열어 끝까지 읽고, 모르는 주소 · 보내기 · 지우기가 있으면 설치하지 않습니다. 내가 만든 스킬도 회사 밖으로 나눌 때는 예시 파일에 고객 정보가 없는지 봅니다.

8. 정리 · 자주 묻는 질문 · 안 될 때

한 줄 요약

사람에게 넘길 수 있는 작업지시서가 먼저, 스킬은 그걸 담는 그릇입니다. Claude는 description 한 줄을 보고 꺼내니 무엇 · 언제를 분명히. 결과가 틀리면 스킬을 고치고, 남의 스킬은 읽고 설치합니다. 03차시에는 이 스킬을 정해진 시간에 알아서 돌립니다.

질문답
Project 지침에 넣으면 안 되나요?그 Project에서만 쓸 거면 지침도 됩니다. 여러 곳에서 쓰거나 Code · 예약 작업에서도 부르려면 스킬이 낫습니다.
스킬을 몇 개까지 만들어도 되나요?많아도 평소엔 이름 · 설명만 읽혀 가볍습니다. 다만 description이 겹치면 엉뚱한 게 불리니, 비슷한 스킬은 하나로 합칩니다.
팀원과 같이 쓰려면?스킬 파일을 전달하거나, 폴더 스킬이면 폴더째 공유. 조직 요금제라면 관리자가 팀 전체에 배포할 수도 있습니다.
