AI Agent 1 · 01차시

AI Agent 이해

챗봇과 에이전트가 무엇이 다른지, 에이전트가 어떻게 일을 끝내는지, 어디까지 믿고 맡길 수 있는지 정리하고 Claude 가입·결제까지 마칩니다.

Claude (PC)이메일 또는 Google 계정
오늘의 가상 상황

당신은 작은 회사의 마케팅 담당자입니다. 팀장이 말합니다. "요즘 다들 AI로 일한다던데, 우리도 'AI 동료' 하나 들이자. 자네가 먼저 써 보고 팀에 알려줘." AI 동료가 대체 뭐지? 챗봇이랑 뭐가 다르고, 돈은 어떻게 내지? 회사 자료를 올려도 되나? 오늘 이 질문들을 끝냅니다.

1. 답하는 AI에서 일하는 AI로

AI 70년 역사는 프롬프트 엔지니어링 과정에서 봤습니다. 오늘은 그 마지막 장면, 챗봇 이후부터 이어 갑니다.

  • 2022챗봇 대중화, 묻고 답하는 AI

    ChatGPT가 공개되면서 누구나 AI와 대화하게 됩니다. 물으면 말로 답하고, 방법을 알려 줍니다. 하지만 거기까지입니다. 답을 읽고 엑셀을 열고, 복사해 붙이고, 실제로 실행하는 건 여전히 사람의 몫이었습니다.

  • 2023–2024도구를 쥔 AI

    AI가 검색을 하고, 올린 파일을 읽고, 코드로 계산하고, 문서·코드를 직접 만들어 냅니다. 사람은 무엇을 원하는지 말하고 결과를 확인하면 됩니다. 말만 하던 AI가 처음으로 손에 도구를 쥔 셈입니다.

  • 2025–지금에이전트, 일을 끝내는 AI

    이제는 목표만 주면 AI가 스스로 계획을 세우고, 여러 단계를 이어서 일을 끝까지 처리합니다. 사람은 일을 맡기고, 결과를 검수하고, 최종 판단을 내립니다. 이것이 오늘부터 배울 AI 에이전트입니다.

한 줄 요약

묻고 답하던 AI가 → 도구를 쥐었고 → 이제 일을 맡아 끝냅니다. 프롬프트 과정에서 배운 "AI에게 정확히 말하는 법"이 여기서 그대로 쓰입니다. 달라지는 점은 하나, AI가 말만 하는 게 아니라 손을 쓴다는 것. 우리는 그 출발선에 서 있습니다. 늦지 않았습니다.

2. 챗봇과 에이전트

챗봇은 텍스트로 묻고 텍스트로 답을 받습니다. 에이전트는 파일을 주고 "읽고, 처리하고, 결과물을 만들어 줘"라고 시키면 도구를 써서 여러 단계를 알아서 처리합니다. 같은 요청 "이번 달 매출 정리해 줘"에 대해:

기존 챗봇AI 에이전트
반응"엑셀에서 SUM 함수를 쓰세요"파일을 직접 읽고 계산·표·차트까지
도구 사용못 함 (말로만)함 (파일 열기, 계산, 작성)
결과방법을 받음결과물을 받음
내 역할내가 다 한다확인하고 다듬는다
비유길을 물으면 "저기서 우회전하세요"라고 알려 주는 행인"목적지요? 타세요, 모셔다 드릴게요" 하는 운전기사
한 문장 정리

챗봇은 답을 주고, 에이전트는 일을 끝낸다.

3. 에이전트 동작 방식 맛보기

실습 A — 사람이 하는 방식 vs 에이전트가 하는 방식

① 사람이 직접: "컴퓨터 예약 종료 방법"을 검색해 명령어를 찾고, 명령 프롬프트(cmd)를 열어 복사·붙여넣기 합니다.
shutdown -s -t 3600 (1시간 뒤 꺼짐) → shutdown -a (취소)
② 에이전트에게: "30분 뒤에 컴퓨터 종료 예약해 줘"라고 말하면, 에이전트가 명령어를 찾아 직접 실행합니다.
같은 일을 누가 손을 움직였는지 비교해 봅니다.

참고
  • 취소 알림이 안 보여도 정상 · 알림 설정이나 PC 정책에 따라 팝업만 안 뜰 수 있음

4. 에이전트는 어떻게 "일을 끝내나"

마법이 아닙니다. 사람이 일하듯 같은 순서를 반복합니다.

단계하는 일매출 정리 예종료 예약 예
① 목표 이해무엇을 원하는지 파악매출을 정리하라는 거구나30분 뒤에 끄고 싶구나
② 계획어떤 순서로 할지 짠다파일 열기 → 합계 → 표 → 요약명령어 찾기 → 예약 실행
③ 행동도구를 실제로 쓴다파일 읽기, 계산, 작성shutdown 명령 실행
④ 관찰결과가 맞는지 확인숫자가 이상한데? 다시예약이 걸렸는지 확인

목표를 이룰 때까지 ②~④를 스스로 반복하는 것이 핵심입니다. 신입 사원이 "어, 이거 아닌가? 다시 해 볼게요" 하는 것과 같습니다.

가장 중요한 단계는 ③ 행동

도구를 쓸 수 있어야 진짜 에이전트입니다. 폴더를 통째로 맡기는 Cowork, 파일·코드를 직접 다루는 Claude Code가 그런 도구입니다. 구글 드라이브·노션 같은 서비스를 잇는 커넥터, 그 연결의 표준 규격인 MCP도 뒤에서 배웁니다. 지금은 "그런 콘센트가 있다"만 기억하세요.

5. 잘하는 일, 약한 일

기대를 현실적으로 맞춰야 실망하지 않습니다.

잘하는 일약한 일 (사람이 챙길 것)
초안 쓰기 (보고서·메일·기획서의 0→1)사실 확인 — 가끔 그럴듯하게 틀림(할루시네이션). 숫자·인용은 검증
긴 문서 요약, 자료 비교·정리최신 정보 — 학습 시점 이후 일은 모를 수 있음
데이터 분석·표·차트회사 내부 사정·관계 — 알려 주지 않으면 모름
반복적이고 규칙이 있는 작업, 형식 바꾸기 (보고서→메일→슬라이드)최종 책임·판단 — 결정과 책임은 항상 사람
검색하면 최신 정보도 알지 않나요?

검색 기능을 쓰면 방금 찾은 페이지 내용은 압니다. 하지만 검색 없이 원래 아는 지식에는 한계가 있고, 찾은 내용도 틀리게 요약할 수 있습니다. 그래서 찾아온 정보도 검증이 필요합니다.

황금률

AI를 "똑똑하지만 가끔 틀리는 유능한 인턴"으로 대하세요. 일은 맡기되, 결과는 사람이 검수합니다.

6. AI 에이전트의 종류

여러 회사가 에이전트를 만듭니다. 모두 훌륭하지만 성격이 다릅니다.

기준Claude (Anthropic)Codex (OpenAI)Antigravity (Google)
성격폭넓은 업무 동료코딩 특화여러 에이전트를 나눠 돌리는 개발 작업 특화
잘하는 일문서·메일·기획·분석·요약 전반코드 작성·수정·자동화복잡한 개발 작업 병렬 처리, Google 생태계 연동
대상누구나 (비개발자 포함)주로 개발자주로 개발자·개발팀

모델 이름은 자주 바뀌니 외우는 데 힘쓰지 마세요. 중요한 질문은 하나, "이 도구가 내 일에 맞나"입니다.

7. 왜 Claude인가, 그리고 가입

Claude를 만든 Anthropic은 2021년 OpenAI 출신 연구자들이 세운 회사입니다. "AI를 더 크게"보다 "AI가 강력해질수록 안전하게 만드는 법을 먼저 연구하자"는 문제의식에서 출발했습니다. 이름은 '인류(anthropos)'에서 왔고, Claude는 스스로 정직·무해 원칙을 따르도록 훈련하는 헌법적 AI(Constitutional AI) 방식으로 만들어집니다.

  • 이 과정은 코드가 아니라 문서·데이터·보고·조사 같은 일반 업무를 다룹니다
  • Claude는 사무 업무 전반에 폭넓게 쓰이고, 필요하면 Claude Code로 자동화까지 — 이 과정의 메인 도구
  • "뭐가 더 똑똑하냐"보다 "내 일에 누가 더 맞느냐"가 옳은 질문

도구는 빠르게 바뀝니다. 그래서 이 과정은 버전 암기가 아니라 에이전트와 일하는 방식을 연습합니다.

실습 B — Claude 무료 가입

① claude.ai 접속 → ② 이메일 또는 Google 계정으로 가입 (카드 등록 없음) → ③ 언어를 한국어로, 화면 둘러보기. 오늘은 무료 계정이면 충분합니다.

준비물
  • 이메일 또는 Google 계정 · 인증 메일이 안 오면 스팸함 확인

8. 회의록 정리해 보기

챗봇과 에이전트의 차이, 에이전트의 반복 과정을 손으로 느껴 봅니다.

실습 C — 방법을 받을까, 결과물을 받을까

① 챗봇처럼: "회의록 양식 하나 만들어 줘. 항목은 일시·참석자·안건·결정사항·할 일." → 이건 방법일까요, 결과물일까요?
② 에이전트에게: 회의록 파일 하나를 끌어다 올리고 "이 회의 메모를 위 양식에 맞춰 정리해 줘. 특히 할 일은 담당자와 마감을 표로 뽑아 줘."
③ 이어서 묻기: "이 회의에서 내가 챙겨야 할 일만 따로 뽑아 줘", "다음 회의 안건도 제안해 줘"
④ 비교 실험: 새 대화에서 파일도 양식도 없이 "회의록 정리해 줘"만 입력. Claude가 무엇을 되묻는지 봅니다 — 맥락을 줘야 한다는 다음 차시 주제가 여기서 나옵니다.

준비물
  • 실습 회의록 3개 · 마케팅 정기회의 / 신제품 킥오프 / 주간 업무공유 — 강사가 당일 배부
팁

AI에게 간략하게 시켜도 잘 처리합니다. 다만 회사마다 회의록에 들어가야 할 항목이 다르니, 그 부분은 꼭 분명히 알려 주세요.

미리 보기

양식을 한 번 만들어 두면, 뒤 차시에서는 Claude가 템플릿 불러오기 → 문서 생성 → PDF 변환 → 확인 → 저장까지 여러 단계를 스스로 이어서 끝냅니다. 4절의 반복 과정이 길게 늘어난 모습입니다.

조절 구간 — 가입·업로드가 막힌 수강생 돕기 / 빠른 수강생은 나머지 회의록 2개도 같은 방식으로 정리하거나, "다음 회의 전까지 내가 할 일과 놓치면 안 되는 마감만 표로"처럼 더 구체적으로 시켜 결과 비교

9. 에이전트의 자율성 단계

자율주행차에 레벨이 있듯, 에이전트도 얼마나 스스로 움직이는지에 따라 단계가 다릅니다.

단계특징이 과정에서
L0 — 그냥 챗봇묻고 답만. 도구 없음실습 C ① 양식만 받기
L1 — 한 번 도구 사용파일 하나 읽고 결과 하나실습 C ② 회의록 정리
L2 — 여러 단계 스스로계획 세우고 여러 도구를 순서대로AI Agent 1 대부분의 차시
L3 — 폴더·과제 단위로 맡기기통째로 맡기면 알아서 다단계 수행Cowork (AI Agent 2)
L4 — 도구로 만들어 재사용반복 작업을 도구로 만들어 계속 실행Claude Code (AI Agent 2)

단계가 높아질수록 편하지만 검수가 더 중요해집니다. 오늘은 L0~L1을 맛봤습니다. 내 업무 중 "방법은 아는데 시간만 잡아먹는" 반복 작업 3개를 적고, 각각 어느 단계까지 맡길 수 있을지 상상해 보세요.

10. 왜 지금, 왜 업무인가 — AX

  • AX = AI Transformation. 디지털 전환(DX)을 넘어 일하는 방식 자체를 AI와 함께 바꾸는 것
  • AI가 사람을 대체하는 게 아니라 사람 + AI가 한 팀 — 반복·단순·시간 잡아먹는 일은 에이전트에게, 판단·책임·관계·최종 결정은 사람에게
  • "AI가 내 일을 뺏는다"보다 "AI를 잘 쓰는 동료가 내 일을 뺏는다"에 가깝다
  • 이 과정의 목표: 각자의 실제 업무 하나를 에이전트와 함께 다시 설계하는 것
